Planning Decisions — 2026-07-24
Railway native Slack integration over custom webhook
If the dispatcher is mid-deploy, it can't receive its own webhook — the notification would never fire during the exact moments that matter. Railway's native notification fires from Railway's side regardless of app state. Zero maintenance surface.
Drive JSON log for OS activity tracking
Consistent with existing drive-store.js pattern (readDriveJson/writeDriveJson). Persists across Railway deploys (no ephemeral filesystem). No new infrastructure required.
Session summary agent runs daily at 5 AM Halifax
Elizabeth works late (sessions to ~2 AM). A 5 AM run captures the previous day including late-night work, before the 6 AM daily briefing. Daily (not weekly) because decisions accumulate fast enough that a weekly batch would lose context.
Don't add new Slack channels — all narration folds into existing ones
The channel routing is already logical. New channels add to the reading load. Casey scan → #northlight-build-log. Advisory/Round Table doc links → #northlight-pmo. OS activity → daily briefing. Session summaries → #northlight-build-log.
GitHub build log scope stays northlight-dispatcher only — correct as-is
All OS code lives in the dispatcher repo. Casey reviews every commit there. Other repos (website, Vault, Meetings) don't need Casey review or dispatcher notification. No change needed.

Context — Why This Matters
📊
The autonomy boundary
Below it (advisory/automated tasks), logs + evals are enough. Above it (decisions with consequences), decision records are required. Northlight OS sits at the boundary — it automates tasks AND surfaces decisions.
🔇
Silent runtime is the core gap
Casey scan, standing PMO, advisory board finalize, round table finalize — all complete with no Slack confirmation. You only know they ran if you check Railway logs (which rotate after ~10 days).
🧠
Session decisions are lost
Claude Code sessions produce real decisions — what to build, what to defer, why. None of this appears in any searchable record. The commit lands and Casey reviews the code, but the reasoning that shaped it lives only in the session.
