Key Decisions
LinkedIn spec in loadGroundingContext(), not a Promise.all fetch
The spec is a static file in specs/ — reading it synchronously with other doctrine files (no I/O gap) is simpler and cleaner than a separate async load. The persona gate (harper | jordan) lives in buildSystemPrompt() where it can check activePersonaIds.
Round Table writes to ClickUp description, not Drive
The content-strategist already reads the parent task description for all other context (platform, audience, raw idea). Writing the RT direction there too means the pipeline reads one source without a new dependency. ClickUp PUT is non-fatal — failure logs to Railway but doesn't block finalize.
googleapis@174 upgrade verified safe
Breaking changes in v174 are TypeScript-only. The runtime auth pattern — google.auth.OAuth2 with transporter: googleTransporter (Gaxios + node-fetch, keepAlive: false) — is unchanged. Both root and dashboard packages upgraded.

Phase 12 Learnings
Advisory board outputs need OS anchors within the same session
The LinkedIn strategy was finalized at an advisory board session on August 3 and required a full follow-on phase (Phase 12) to wire into the OS. For future advisory board decisions that create execution obligations, identify which OS components need updating and create those tasks immediately — don't wait for the next session to discover the gap.
Task description as the pipeline's shared data layer
The pattern of writing back to the ClickUp task description (Round Table direction → campaign task) makes the task description a shared data layer between tools that don't otherwise communicate. It leverages the existing extractSection() infrastructure without adding new storage dependencies. Watch for description-length limits if more sections accumulate.
npm audit exit code 1 ≠ failure when the remaining issues need --force
npm audit fix exits with code 1 when outstanding vulnerabilities remain (even if it successfully applied non-breaking fixes). The test is the audit output text ("found 0 vulnerabilities"), not the exit code. Checking the text before alarming prevents false failures in scripted contexts.
