Key Decisions
Dual-purpose checkmark, no new button
The existing checkmark in IntelligencePanel already meant "I find this interesting." Flagging for intake is the same signal. Adding a second button would have split Elizabeth's intent across two clicks and created UI noise.
Auto-score at 5pm, not user-triggered
Elizabeth explicitly: "If I can forget to click it when I get busy, I will. Let's reduce my friction." The 5pm Atlantic job fires whether or not she remembers — uses same Halifax self-rescheduling pattern as the morning dispatcher.
Haiku for trend scoring, not Opus
Scoring 2–6 articles and picking the best one is a lightweight classification task. Haiku is sufficient and keeps cost low — Opus is reserved for strategy briefs and Round Table sessions where reasoning depth matters.
Repurpose mode detected from POST SOURCE field
No new task type needed — the strategist reads POST SOURCE from the parent task description (existing infrastructure). "Repurpose —" prefix is the trigger. Keeps the pipeline uniform; repurpose tasks go through the same subtask chain as new posts.
Research skipped but ENHANCEMENT AVAILABLE allowed
Repurpose tasks have source material — running research is redundant and slow. But the strategist can flag enhancement opportunities (fresh stats, current examples) as non-blocking notes. Elizabeth decides whether to act on them.
Learnings
Dual-purpose UI reduces friction better than a new trigger
Reusing the checkmark means Elizabeth's workflow is unchanged — she just checks articles she finds interesting, same as before. The intake flag is a free side-effect. Adding a new "flag for intake" button would have created a choice where the right answer is always "both."
Auto-scheduling at a fixed time beats user-triggered for regular jobs
User-triggered scoring means it doesn't run when Elizabeth is busy — which is exactly when the backlog builds up. The 5pm Halifax timer fires reliably every day regardless of calendar, replicating the pattern established by the morning dispatcher and marketing runs.
POST SOURCE as a mode signal is clean and extensible
Using POST SOURCE: Repurpose — [platform] — [url] as the mode trigger means the strategist can detect it from existing field-parsing infrastructure with one startsWith() check. No new task type, no new database field, no routing change — and it's visible to Elizabeth in ClickUp.
setImmediate() is the right pattern for fire-and-forget in Express routes
The repurpose route needs to return immediately while the strategist runs asynchronously. setImmediate() defers to the next event loop iteration — cleaner than a floating IIFE with its own timeout, and it correctly yields control back to Express before the long skill job starts.
