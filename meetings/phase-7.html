Paddle Appeal — Detail
What Happened

Paddle's domain review flagged bynorthlight.ca under two categories: Human Services / Consulting or Advisory Services and Human Services / IT Services or Software Development Services. Both fall outside Paddle's Acceptable Use Policy for Merchant of Record accounts.

Why: Paddle's risk team reviews the entire domain, not just the product. Because bynorthlight.ca primarily describes a consulting and advisory firm, the automated review flagged the whole account — even though Northlight Meetings is a standalone software product being sold independently.

Appeal argument submitted: Northlight Meetings is a Windows desktop application sold as a one-time purchase at $299 CAD. It is software, not a consulting service. No consulting or advisory work would be transacted through Paddle. The consulting content on the domain relates to a separate business line not sold through Paddle.

Expected decision: ~2026-08-19 (3 business days). Fallback if denied: Lemon Squeezy — same Merchant of Record model, less strict domain review, popular with indie software developers.

Key Learnings
Paddle simulation payloads exclude customer.email — always will
Simulations send customer_id only. Real transactions also don't expand the customer object. The fix is a Paddle API GET /customers/{id} call — which requires a server-side API key (not the client token). Always test fulfillment with a real sandbox purchase, not a simulation.
Express middleware ordering is critical for HMAC webhook verification
express.raw() must be registered before express.json() globally. Once express.json() parses the body, req.body is an object — req.body.toString() returns "[object Object]", not the raw JSON string. HMAC verification fails silently. Unauthenticated webhooks must mount before any body-parsing middleware.
Express router path stripping catches you when mounting with app.use()
When mounting a router with app.use('/api/paddle/webhook', router), Express strips the prefix before the router sees the request. The handler inside the router must be router.post('/'), not router.post('/api/paddle/webhook') — otherwise the route never matches.
Private GitHub repos 404 for anonymous installer downloads
GitHub release asset URLs require authentication for private repos — buyers get a 404. The installer is a distributed binary with no secrets in it. Making the repo public is the correct and simplest solution. Alternative: S3/R2 with a public bucket policy.
Paddle domain review assesses the whole site, not just the product
Paddle's automated review flagged bynorthlight.ca as a consulting firm, not a software company — even though the product being sold is standalone software. If your main domain describes consulting services, a Paddle application for software sold on the same domain may be rejected. Appeal is viable; Lemon Squeezy is a clean fallback with the same MoR model.
