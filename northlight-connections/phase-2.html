Where it stands
Phase 1 followed Draft 1 to real daily use; Phase 2 made it fit the ISO policies and added the three agreed extras. Backups are now encrypted and kept to the newest two; any person's data can be exported and people missing for a year come up for review. Reminders live inside the app instead of ClickUp: a 9:00 AM notification, a tray icon, snooze and a profile button. Claude can read the contacts through a local, read-only connector that is off by default, never describes clients, and keeps a log of every question. Coffee chats in an exported Google Calendar are matched to people and set to Held or Booked after Elizabeth confirms each one. The ISMS and AIMS pages, the registers and the public privacy policy were updated to match. All of it runs on the real data and has been tried by Elizabeth.

Decisions
Local-by-design exception, with encrypted backups
The contacts file stays on the laptop; encrypted backups make that acceptable against the cloud-first policy. (Elizabeth, Nov 11)
Reminders live inside the app, not in ClickUp
A reminder with no name or link was useless, and ClickUp would hold third-party profile links. Notification at 9:00 AM, tray, start with Windows. (Elizabeth, Nov 11)
Clients are always an ID and a stage in the Claude connector
Keeps client personal information out of AI tools at every level, as AIMS-004 requires. (Elizabeth, Nov 11)
12-month retention review; export a person; contacts-register row
Fills the retention and access-request gaps for about 2,000 third parties. (Elizabeth, Nov 11)
No MCP software package
The protocol part is about 60 lines, so no new dependency or alert source. (Claude Code, Nov 12)
Keep only the newest two backups
Limits how long a forgotten person can survive in old backups. (Elizabeth, Nov 12)
Calendar through an exported file, with confirmation on every match
No Google sign-in or key; nothing is stored but date and person. (Elizabeth, Nov 11)

Learnings
The Claude desktop app from the Microsoft Store redirects files its child programs write under AppData
A stray test copy of the data folder hid the real database from the connector. Never run the app against the default data folder from a development session; the connector now detects it.
Fake test names must differ in letters, not digits
Matching ignores digits, so "Test01" and "Test02" looked identical and hid a matching problem until real names arrived.
Real LinkedIn surnames carry credentials
"Surname, CPA" broke last-word matching; credentials are now ignored.
Append, do not rewrite, ISMS pages
The page markdown ClickUp returns can flatten tables, so amendments were appended and the one full-page edit was checked line by line.
